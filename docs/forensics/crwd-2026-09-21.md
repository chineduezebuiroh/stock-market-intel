# CRWD 2026-09-21 forensic reconstruction contract

`diagnostics/reconstruct_stock_asof.py` is a read-only follow-up to the immutable
combo-lineage collector. It exists because rolling bars and snapshots are not an
application-level immutable archive. The prior repository forensic pattern in
`.github/scripts/export_s3_forensic_window.py` reads the current rolling daily
object and truncates it to the requested date; it does not recover an original
provider payload. The scoring-lineage collector later attempted S3 object-version
selection, but correctly reports unavailable evidence rather than substituting
the latest object.

The reconstruction fetches unadjusted Yahoo daily bars (`auto_adjust=False`, no
actions) with an exclusive end of 2026-09-22, rejects every local market date
after 2026-09-21, and aggregates those eligible observations into Monday-labelled
weeks and month-start-labelled months. Thus the 2026-09-21 weekly bar contains
Monday only and may legitimately equal the daily OHLCV. The September monthly bar
is month-to-date, never the subsequently completed September candle. Eight years
of daily input exceeds the configured 126-daily, 104-weekly, and 60-monthly
percentile warmups.

This is not exact historical production evidence: Yahoo can revise old data, and
production requests Yahoo's `1d`, `1wk`, and `1mo` intervals independently. The
diagnostic therefore labels its results as a present-day provider reconstruction
and supports a separately supplied immutable combo parquet for comparison.

No production scoring, indicators, storage, jobs, workflows, or dashboard code
is invoked or changed by this diagnostic. Outputs are local CSV/JSON files only.
